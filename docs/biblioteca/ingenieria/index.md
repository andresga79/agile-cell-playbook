# Ingeniería

Fichas sobre las prácticas técnicas y las métricas que sostienen la entrega frecuente: cómo trabaja un equipo que cambia el software a menudo sin romperlo, cómo se acuerda el comportamiento con ejemplos y cómo se mide la entrega sin reducir a las personas a un número. Están escritas para leerlas sin ser developer.

| Ficha | En una frase |
|---|---|
| [Extreme Programming (XP)](xp.md) | Valores, principios y prácticas para que cambiar el software siga siendo barato |
| [BDD](bdd.md) | Acordar el comportamiento con ejemplos y convertirlos en pruebas automáticas |
| [Trunk-based development](trunk-based.md) | Integrar en una sola rama principal, al menos una vez al día |
| [DORA](dora.md) | Cinco métricas de rapidez y estabilidad de la entrega, y su lead time distinto |
| [SPACE](space.md) | Cinco dimensiones para hablar de productividad sin una métrica única |
