# Producto

Fichas sobre cómo un equipo decide qué construir y por qué: hablar con clientes cada semana, conectar el trabajo con metas medibles y entender qué progreso busca la gente. Sirven sobre todo para acompañar al Product Owner y para notar cuándo un backlog es solo una lista de pedidos.

| Ficha | En una frase |
|---|---|
| [Continuous discovery](continuous-discovery.md) | El equipo que construye habla con clientes cada semana y prueba supuestos antes de construir |
| [OKRs](okrs.md) | Un objetivo y pocos resultados clave medibles, revisados en un ciclo corto |
| [Impact mapping](impact-mapping.md) | De la meta de negocio a actores, cambios de comportamiento y, al final, entregables |
| [Jobs to be Done](jtbd.md) | Entender el progreso que alguien busca, y sus dos escuelas: Christensen y Ulwick |
| [Shape Up](shape-up.md) | El método de Basecamp: apetito, apuestas y ciclos de seis semanas, y dónde choca con Scrum |
