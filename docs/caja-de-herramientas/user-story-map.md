# User Story Map

**Fase:** 1 · **Origen:** Jeff Patton · **Duración:** 2 a 4 horas

## Estructura

```
Actividades →   [Descubrir]       [Solicitar]          [Pagar]          [Hacer seguimiento]
(columna        ─────────────────────────────────────────────────────────────────────────
 vertebral)
Tareas →        Buscar producto   Completar datos      Elegir medio     Ver estado
                Ver detalle       Subir documentos     Confirmar pago   Recibir aviso
─────────────── Release 1 · MVP (persigue el MVO) ─────────────────────────────────────
Historias       Buscar por        Formulario           Pago con         Correo con
                nombre            básico               tarjeta          estado
─────────────── Release 2 ─────────────────────────────────────────────────────────────
                Filtros           Validación auto.     Pago en cuotas   Notificación push
─────────────── Release 3 ─────────────────────────────────────────────────────────────
                Recomendaciones   Autocompletar        Billetera        Chat de soporte
```

## Pasos

1. **Narrar el recorrido** del usuario de punta a punta (actividades, de izquierda a derecha).
2. **Desglosar** cada actividad en tareas.
3. **Explorar** variantes, excepciones y alternativas bajo cada tarea (historias).
4. **Cortar releases**: la primera línea contiene lo mínimo para recorrer todo el flujo y lograr el MVO.
5. **Asociar outcome** a cada release: ¿qué métrica esperamos mover?
6. Trasladar la primera release al backlog (Jira: épicas = actividades, historias = tarjetas).

## Reglas

- La primera release debe permitir recorrer **todo** el flujo, aunque sea de forma básica (rebanada vertical).
- Revisar el mapa en cada revisión con negocio; es un artefacto vivo.
